## 🧠 模式一：多 Agent 路由（配置级）

一个 Gateway 进程里跑**多个独立的 Agent**，每个有自己的 workspace、人格、渠道绑定：

```
Gateway
├── Agent "main"      → 你的日常助手（微信/Telegram）
├── Agent "coding"    → 代码专用 Agent（Discord）
├── Agent "family"    → 家庭群 Agent（WhatsApp）
```

每个 Agent 独立配置：
- 不同的 `SOUL.md` / `AGENTS.md`（不同人格）
- 不同的 workspace（文件隔离）
- 不同的 model（便宜的做日常，贵的做深度工作）
- 不同的 tool 权限（家庭 Agent 禁写文件，个人 Agent 全权限）

配置方式：
```bash
openclaw agents add coding    # 创建新 Agent
openclaw agents add family    # 再创建一个
```

然后在 `openclaw.json` 里配 `bindings` 指定哪个渠道消息路由到哪个 Agent。

---

## 🔀 模式二：子 Agent 后台并行（工具级）

一个主 Agent 用 `sessions_spawn` 工具**派生子 Agent 去后台干活**：

```
你 → 主 Agent（回答你的问题）
         ↓ sessions_spawn
         ├── 子 Agent 1：帮我搜 10 家公司岗位
         ├── 子 Agent 2：帮我改英文简历
         └── 子 Agent 3：帮我写项目文档
              ↓ 干完自动回报
         主 Agent → 汇总结果发给你
```
